# 高考英语作文智能批阅 · 应用文 15 分 / 读后续写 25 分

给高中英语老师用的作文批改平台。拍学生作文 → 自动识别文字 → 按高考英语五档标准打分 → 出报告（含档位判定、维度细评、扣分明细、原文升格示范、提分路径）→ 导出 Word。

> 这是「语文作文批改平台」的英语版，界面与流程沿用同一套，**评分内核整体换掉**。

---

## 一、两种题型，两套标准

| 题型 | 满分 | 五档 | 维度拆解 |
|------|------|------|----------|
| 应用文写作 | 15 | 13-15 / 10-12 / 7-9 / 4-6 / 0-3 | 内容要点 6 · 语言准确 5 · 篇章连贯 2 · 格式语域 2 |
| 读后续写 | 25 | 21-25 / 16-20 / 11-15 / 6-10 / 0-5 | 情节逻辑 8 · 语言表达 8 · 衔接连贯 5 · 结尾升华 4 |

### 内置的硬性扣分规则

**应用文**
- 3 个要点缺 1 个 → 扣 3–4 分；缺 2 个 → 总分压到 6 分以下
- 书信无称呼/无落款、时态混用 → 扣 1–2 分
- 主谓不一致、时态错乱、搭配错误、高频词拼写错误，累计每 3 处 → 降一档
- 不足 60 词扣 2–3 分；不足 40 词直接判低档

**读后续写**
- 情节断层 / 人设崩塌 / 逻辑矛盾 → 直接降 2 档
- 只写一段或两段严重失衡 → 扣 5–8 分
- 两段合计不足 100 词 → 降一档
- 不接所给段落开头语、大段抄原文 → 降档
- 冲 21 分以上须满足：高级句式≥3 处 + 细节描写 + 结尾升华

### 给分纪律（写进 Prompt，强制模型遵守）

1. 先把原文完整读一遍（含拼写、标点、分段）再评分
2. 五档是硬边界，只能给档内分数，档内最多 ±1，**不许跨档**
3. 拿不准一律往下压一档（给低了能解释，给高了改不回来）
4. 总分 = 各维度之和 + 扣分项，算不通就重算
5. 总分高于高档线（应用文 13 / 续写 20）必须在 `tierReason` 里逐条说明凭什么够高档
6. 引用原文必须真实存在，不许编造学生没写过的句子
7. 升格示范要给完整英语原句，不许写"可考虑使用更高级词汇"这类空话

## 二、三种运行模式

顶栏「设置」里切换：

| 模式 | 用途 | 是否需要 Key |
|------|------|--------------|
| **Mock 模拟** | 首次打开默认走这个，载入示例即可看完整报告效果，不耗额度 | 不需要 |
| **Edge 代理** | 部署后的正式模式。DashScope Key 存在 Supabase Secrets，前端永不暴露 | 需要 Supabase 函数地址 + publishable key |
| **通义直连** | 仅本地测试。浏览器直连 DashScope | 需要 sk- 开头的 Key（部署前务必清空） |

## 四、本地怎么跑（本机自用最省事）

### 1. 先看效果，不需要任何 Key

双击 `index.html` → 点「应用文写作」或「读后续写」→「载入示例作文」→ 一路走到报告页。
默认 Mock 模式，不调任何接口，报告结构、Word 导出、历史记录都是真的。

### 2. 要真实打分，填一次 Key 就行

1. 阿里云百炼控制台 → API-KEY 管理，复制 `sk-` 开头的 Key
2. 平台右上「⚙ 设置」→ 运行模式选 **⚠ 通义直连 · DashScope（本地测试用）**
3. 粘贴 Key → 点 **🔍 测试 Key 是否可用**（用 qwen-turbo 打一句招呼，几乎不花钱）
   - 显示 `✅ 通义千问连接成功` 就通了
   - `InvalidApiKey` / 401 → Key 复制错或没开通百炼
   - `model not found` → 去百炼「模型广场」把 qwen-plus 和 qwen-vl-ocr 各点一下「开通」
4. 点保存（设置会存本机，**刷新页面不用重填**）

### 3. 不用拍照也能评分

第一步有「**✍ 不上传图片，直接粘贴文本**」按钮：跳过 OCR，直接把电子稿粘进「作文正文」，题目可选填。
验证 Key、批电子稿、批打字稿都用这条最快。

### 4. 想用本地服务（推荐，避免 file:// 的个别限制）

```bash
cd english-composition-platform
python -m http.server 8848
# 浏览器打开 http://localhost:8848
```

> Key 存在浏览器 localStorage，F12 能看到。这是「本机自用」的定位；
> 要给学生或同事用，必须走 Edge 模式把 Key 挪到 Supabase Secrets。

## 五、部署（⚠️ 先看这条）

### 千万不要直接在语文版那个 Supabase 项目里部署

函数名相同（`score` / `ocr` / `login` / `report` / `change-password`），**部署会覆盖语文版的评分逻辑**，语文平台当场就会按英语标准给分。

正确做法二选一：

**A. 新建一个 Supabase 项目（推荐）**

1. 新建项目 → 把本项目 `supabase/functions/` 下的函数全部部署进去
2. 在 Project Settings → Edge Functions → Secrets 配置下面这些变量
3. SQL Editor 建表（首次登录会自动建 `teacher_accounts`，`reports` 首次存取时自动建）
4. 前端「设置」里把 Function 地址改成新项目的 `https://<新ref>.supabase.co/functions/v1`，填 publishable key，模式切 **Edge**
5. `index.html` 可继续放 GitHub Pages

**B. 同项目部署但改函数名**

把目录名改成 `score-en`、`ocr-en` 等，同时改前端 `edgeBase() + '/score'` 里的路径。麻烦，不推荐。

### Secrets 清单

| 变量 | 必需 | 说明 |
|------|------|------|
| `DASHSCOPE_API_KEY` | ✅ | 阿里云百炼 Key，评分与识别都靠它 |
| `AUTH_JWT_SECRET` | ✅ | 教师令牌签名密钥，随便一串长随机字符 |
| `SUPABASE_DB_URL` | ✅ | 数据库连接串（Project Settings → Database） |
| `TEACHER_ACCOUNTS` | 首次 | 首次登录引导用，通过后密码哈希落库，格式参考语文版 README |
| `STUDENT_PASS` | 可选 | 学生入口班级口令；不配则学生必须用教师账号登录 |

### 平台层设置

Edge Functions 的 **Verify JWT 保持 Disable** —— 我们用的是自签令牌，不是 Supabase Auth 签发的，打开会把所有请求当 Invalid JWT 拦掉。真正的校验在函数内部。

## 六、两个入口怎么用

落地页就是两张卡：**应用文写作 · 15 分** 和 **读后续写 · 25 分**。点哪个就按哪套标准走，进去后第一步顶部还能临时改题型。

- **应用文写作**：上传写作要求（含 3 个要点）+ 学生作文 → 评分时核查要点覆盖、格式语域、语言错误密度
- **读后续写**：上传阅读材料 + 学生两段续写 → 评分时看情节衔接、高级句式、细节描写、结尾升华

评完可以保存历史、分享报告短链接、导出 Word。历史记录存本地 localStorage，带题型与满分（应用文显示 x/15，续写显示 x/25）。

### 登录与额度

点入口若未登录会先要求登录：教师账号登录一次令牌存 8 小时；也可以配**班级口令**（Supabase Secrets 的 `STUDENT_PASS`）让学生直接进，不用给账号。

- 后端只放行 `ocr` 与 `score` 两个函数，口令错就 401
- 换口令 = 改 Secrets，旧口令立刻失效
- 兜底仍然是阿里云侧的**月度消费上限**（唯一的真限额手段，务必设）

## 七、和语文版的主要差异

| | 语文版 | 英语版 |
|---|---|---|
| 满分 | 60（基础 40 + 发展 20） | 应用文 15 / 续写 25 |
| 档位 | 四等 | 五档 |
| 题型切换 | 无 | 顶部切换器，两套标准各自独立 |
| 报告结构 | 基础/发展 + 十维细评 | 档位判定 + 四维细评 + **扣分明细** + 升格示范 + 提分路径 |
| Word 报告 | /60 | /15 或 /25，第九章结构 |
| 依赖 | unpkg CDN | **本地 vendor**，国内网络也能出 Word |
| 入口设计 | 按身份分（学生 / 教师） | 按题型分（应用文 / 读后续写） |
| 默认模式 | edge | mock（避免误调付费接口） |

## 八、已知限制 / 下一步可做

- **批量批改还没做**：落地页写了「批量批改」，当前一次只处理一份。要做得加一个队列页：多文件 → 逐份 OCR + 评分 → 汇总表格 → 一次性导 Excel。
- **OCR 是逐张串行**：多页作文会一张一张过，慢。可改并行（Promise.all）但要注意 DashScope 限流。
- **历史记录只在本机**：换电脑/清缓存就没了。要云端同步得加一张表 + 教师令牌读写。
- **Word 里的 emoji**：部分字体不显示，属正常现象。
